Technology stack

This page lists every technology used to build, test, ship and run RetailOS: what each one does in the system, why it was chosen, and what was rejected. If a library is not on this page, add it here (with a reason) in the same pull request that introduces it.

How to read the versions The "Version line" column is the major line to start on, as of November 2026. Pin exact versions in build.gradle.kts and package.json, and let Renovate propose updates. Prefer LTS releases, and upgrade a major line only through a planned pull request with the full test suite.

Version and upgrade policy

  • Runtimes: Java and Node stay on LTS lines. Move to the next LTS within 6 months of its release.
  • Frameworks: stay within the supported window of Spring Boot, Electron and React. Electron needs upgrading every few months to keep its Chromium security fixes.
  • Dependencies: Renovate groups minor and patch updates weekly. Security fixes are merged within 14 days (NFR-08). Major upgrades are planned work.
  • Licences: allow MIT, Apache-2.0, BSD, ISC, MPL-2.0 and LGPL (dynamically linked). Anything GPL or AGPL needs approval before it ships inside the product. CI checks licences.
  • New technology: needs an ADR and a row on this page.
