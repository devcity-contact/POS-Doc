API endpoints

Every backend endpoint for the MVP, grouped by the module that owns it: 165 endpoints in 16 modules. Open an endpoint to see who can call it, what it takes and returns, its errors, the screens that use it and its build task. 0 built, 0 being built, 165 planned.

Keep this page up to date
  • When you start an endpoint, set its status="building"; when it is merged and works on staging, status="built".
  • When you add, change or remove an endpoint, change its line in tools/build_endpoints.py in the same pull request as the code.
  • Then run python tools/build_endpoints.py. It rebuilds this page and the build order (which links each task to its endpoints), and stops if a task or screen code is wrong.
  • Once the backend exists, a CI test compares this list with the generated openapi.json, so the two can't drift apart (CORE-15).

Rules for every endpoint

TopicRule
Base paths/api/v1 for the admin app and online register calls, /sync/v1 for register sync (device token only).
TenantAlways taken from the token, never from the path or body. No endpoint has a tenantId parameter (tenant isolation).
Errors on every signed-in endpoint401 AUTH-001 (no or expired token), 403 AUTH-003 (missing permission), 403 TEN-001 (shop suspended), 400 VAL-001 (invalid input), 429 (rate limit). The list under each endpoint shows only the errors special to it. Format: Problem Details.
Money and quantitiesStrings with 4 decimals, e.g. "320.0000" (INV-03). Ids are UUIDv7. Times are UTC ISO-8601.
ListsCursor paging: ?limit=50&cursor=… returns nextCursor.
UpdatesPUT needs If-Match with the ETag from the last read; a mismatch is 412.
RetriesPOSTs that create money or stock records take an Idempotency-Key. Sync push uses each item's id instead.
HeadersSee standard headers; the path a request takes through the filters is in the request pipeline.
