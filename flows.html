FEFO allocation algorithm

allocate(line, location):
  need = line.base_qty
  if line.batch_hint is set:                       # cashier picked it or GS1 scan carried it
      take min(need, onHand(hint)) from hint, or all of need if hint is the only batch
      need -= taken
  candidates = batches(sku, location)
                 where status = OPEN and (expiry is null or expiry >= business_date)
                 order by expiry_date nulls last, received_at, id
  lock candidates FOR UPDATE in id order           # fixed lock order prevents deadlocks
  for b in candidates while need > 0:
      take = min(need, onHand(b)); if take > 0: allocate(b, take); need -= take
  if need > 0:                                     # short stock: never reject (BR-05)
      b = hint or first candidate or most recent batch of sku (even if expired/depleted)
      allocate(b, need)                            # balance goes negative
      raise exception NEGATIVE_STOCK(sku, location, need)
  for each allocation: insert stock_movement(type=SALE, qty=-take, unit_cost=b.unit_cost)

Batch recall (pharmacy)

  1. A manager blocks batch A123 of a SKU for every branch, with a reason.
  2. Inventory sets batch.status = BLOCKED and writes a batches change with high priority.
  3. Registers pull it on the next staff/settings/batches fast cycle (within 60 s while online). From then on, scanning that batch shows a hard stop.
  4. A report lists sales from the batch before the block, with customers where known. These sales stay valid as facts.
  5. Remaining stock is written off or returned to the supplier with stock movements.
