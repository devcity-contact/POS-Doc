Screens & navigation

RetailOS has three front-ends plus printed documents. This page lists every screen with an ID, who uses it, which release it ships in and how it behaves offline. It also specifies the screens that matter most in detail. Visual layouts are on UI design & wireframes.

Try itA working clickable prototype of the register and the Overview dashboard is included in these docs. It covers keyboard shortcuts, scanning (type a barcode and press Enter), the batch picker, weighing, discount with a manager PIN (1234), hold and recall, payment, sale complete, a tablet bottom-sheet layout, dark mode and simulated offline and printer states.

The front-ends

Register app R-xx

The counter. Cashiers, pharmacists and managers. Windows (MVP) and Android (R2). Fully offline. Optimised for speed, scanning and touch plus keyboard.

~21 screens

Admin web A-xx

The back office. Owners, managers, stock keepers, accountants. Any browser, needs a connection. Responsive, with a mobile-friendly dashboard.

~45 screens

Platform console P-xx

DevCity internal. Support and operations. Fleet health, tenants, releases. Part of the admin web, behind the platform role.

~7 screens

Printed outputs D-xx

Receipts, tax invoices, credit notes, Z-reports, labels, statements. These are UI too, and shops judge the product by its receipt.

~8 layouts

Key register screens in detail

R-04 Checkout (home screen)
GoalRing up a typical basket of 5 items in under 20 seconds with a scanner, with no mouse needed.
LayoutTop bar: branch/register, cashier, shift time, sync status, menu. Left (≈60%): scan/search field (always focused), cart lines. Right (≈40%): customer card, totals, quick keys (favourites/categories), action buttons, big Pay button.
Cart line showsName (in the user's language, falling back to English), variant, quantity × unit price, line discount, line total, badges: batch/expiry, Rx (pharmacy), kg (weighed), offer, price changed.
ActionsScan · search F2 · customer F3 · quantity F4 · discount F5 · hold F6 · recall F7 · return F8 · cash in/out F9 · pay F10 · remove line Del · +/− quantity +/- · void sale Ctrl+Del
Scan rulesUnknown barcode: a red toast and a beep, and the code is kept in the search field. GS1 code: batch set automatically. Weight barcode: quantity filled in. Same SKU scanned again: increase quantity on the existing line (configurable).
OfflineIdentical behaviour. The banner shows "Offline · 12 sales waiting". Stock is shown as an estimate.
Dataregister-core Cart, local SQLite catalog/prices/batches. No network calls.
Edge casesExpired batch: warn and confirm (BR-09). Blocked/recalled batch: hard stop. Price older than 24 h offline: yellow banner. Line limit 200.
RequirementsF-101–F-106, F-114, BR-01–BR-04, NFR-01
R-10 Payment
GoalTake payment in one or two key presses for a cash sale. Support split payment.
LayoutAmount due (very large). Payment-type buttons: Cash, Card, LankaQR, Credit (only with a credit customer). A numeric keypad with quick cash buttons (exact, Rs 500, 1000, 5000). A list of payments added. Change due. A "Tax invoice" toggle with a buyer VAT number field.
RulesCard/QR: enter the approval reference (MVP, standalone terminal). Never card numbers (INV-11). Credit: limit check (BR-07). Complete is enabled only when the payments cover the amount due.
CompleteOne local transaction (receipt number + sale + outbox) → print → open drawer if cash → R-11. See sale path.
KeysEnter = exact cash and complete · F1–F4 payment types · Esc back to cart
R-02 Sign-in (PIN)
LayoutUser tiles (photo or initials, name) for staff assigned to this branch. PIN pad. Language switch (සිං / தமி / EN). Sync status. Device name and app version in small text.
Rules5 wrong PINs: 5-minute lockout for that user on this device, audited. Auto-lock after N minutes idle (setting). Switching cashier mid-shift is allowed only when the cart is empty, and each cashier has their own cash session unless the branch uses shared drawers (setting).
R-13 Returns
FlowScan the receipt barcode or type the receipt number → original lines with quantity sold and already returned → choose quantities → reason (damaged, expired, wrong item, customer changed mind, other) → refund method (defaults to original) → manager PIN if above limit → print return slip / credit note.
Without receiptAllowed only with a manager PIN and a product scan. Refund at the lowest recent price (setting).
RequirementsF-107, BR-06, US-03
R-16 Close shift
FlowCart must be empty and no held bills (or transfer them) → count cash by denomination (blind) → card/QR slip totals → see expected vs counted and variance → reason if the variance is above the threshold → print Z-report → sign out.
RequirementsF-502, F-404, BR-08, US-04
R-19 Status & diagnostics
ShowsOnline/offline, last pull and push times, pending/blocked outbox counts (with error codes), catalog cursor, app version, device ID, free disk space, clock skew, printer status, last error.
ActionsTest connection · Sync now · Test print · Open drawer (audited) · Upload logs to support · Full resync (manager PIN).
Why it mattersSupport can ask a shop to read this screen over the phone. It cuts most remote-support calls short (RB-01).

Key admin screens in detail

A-10 Dashboard
Top row (KPI tiles)Sales today · transactions · average basket · gross margin % · compared with the same day last week
MiddleHourly sales chart (today vs last week). Sales by branch (when there is more than one).
Action lists"Needs attention": open sale exceptions, shift variances to approve, registers offline more than 24 h, batches expiring in 30 days, low stock. Each item links straight to the screen that resolves it.
DataMaterialized views refreshed every 5–15 minutes. Shows an "as of" time. Never queries raw sale lines.
MobileTiles stack. Charts become sparklines. "Needs attention" comes first.
A-21 Product editor
PatternFull page with tabs, a sticky Save bar, and an unsaved-changes guard. Optimistic locking (If-Match): on conflict, show "changed by X at time" and offer a reload.
ValidationInline, per field, in the user's language. Duplicate barcode check against the server as you type.
Extension tabRendered by the enabled module through the product.details slot (pharmacy: generic name, strength, form, schedule, Rx required).
A-23 Import wizard
Steps1 Template → 2 Upload (XLSX/CSV, up to 20 MB) → 3 Map columns (auto-matched by header) → 4 Preview: counts plus an error table (row, column, message), downloadable → 5 Commit (progress bar, async job) → 6 Result.
SafetyDry run is the default. Nothing changes before Commit. A large import triggers a new register snapshot.
A-53 Sale exceptions queue
LayoutFilterable table (type, branch, age). A side panel shows the sale, the problem, evidence (e.g. stock at the time, price on the server vs the register) and suggested actions (post the pending GRN, adjust stock, accept the price difference).
RuleResolving never edits the sale (INV-02). Actions create adjustments or notes.
