Guide for AI agents

This page is written for AI coding agents (Claude Code, Copilot, Cursor and similar) and for humans who direct them. It is the most compact statement of how RetailOS must behave. A plain-text copy is in ai/AGENTS.md and ai/system-context.md, and a site index for tools is in llms.txt.

How to give an agent context Copy Doc/ai/AGENTS.md to the repository root as AGENTS.md (and CLAUDE.md if your tool reads that name). For a task, also give the agent the module page and the flow it touches, e.g. "Read Doc/modules.html#details (Sales) and Doc/flows.html#record-sale, then implement F-103."

Invariants (canonical list)

These rules are never broken. Cite the ID in code comments next to the code that enforces it, and in test names.

IDInvariantEnforced by
INV-01Every tenant-owned row has tenant_id. Every DB transaction sets app.tenant_id. RLS is forced on every tenant table.RLS policies, TenantIsolationIT
INV-02A completed sale is a fact: never rejected by the server, never updated, never deleted. Corrections are returns, credit notes or exceptions.DB grants (no UPDATE/DELETE on fact tables), domain model
INV-03Money and quantities are decimals: numeric(19,4)/numeric(14,3), BigDecimal, decimal.js, strings in JSON. Rounding HALF_UP to 2 places for totals.ArchUnit + ESLint rules, test vectors
INV-04Stock changes only by inserting stock_movement rows through the Inventory module. stock_balance is a projection.Module boundary test, nightly ledger check
INV-05Every fact created on a register has a client-generated UUIDv7, which is its idempotency key. Replays return the stored result.sync_inbox, SyncIdempotencyIT
INV-06Receipt numbers are gap-free per register, {branch}-{register}-{seq}, allocated in the same local transaction that completes the sale.Local transaction, receipt_registry
INV-07Tax is calculated only by the Tax module (server) and register-core/tax (register), from configured rules. Extensions never compute tax.Code review, test vectors
INV-08Modules communicate only through their public *Api, events and spi packages. No module reads another's tables (Reporting reads views only).ModularityTest
INV-09The audit log is append-only and hash-chained. The app role cannot update or delete it.DB grants, nightly chain check
INV-10Sale lines snapshot unit price, discount, tax rate and batch cost at the moment of sale.Schema (non-null snapshot columns)
INV-11Card numbers, CVV and track data never enter the system.Design (no fields), code review
INV-12Master data is server-authoritative. Transactional facts are register-authoritative.Sync protocol
INV-13Schema and API changes are backward compatible with the previous release and register version N-1 (expand/contract).MigrationCompatIT, OpenAPI diff
INV-14Batch allocation: an explicit batch (cashier or GS1) wins, otherwise FEFO skipping expired and blocked batches. Rows are locked in batch_id order.Inventory allocation tests
INV-15Timestamps are UTC timestamptz. business_date uses the branch time zone and the cash session's opening date.Schema, tests

Rules for agents

Always

  • Run the module's tests plus ModularityTest before declaring done.
  • Add tenant_id + RLS + an isolation test for every new table.
  • Use the shared Money/Decimal types.
  • Write expand-only migrations, one concern per file.
  • Add i18n keys in all three languages (mark si/ta drafts with "_review": true).
  • Put a requirement ID (F-, BR-, NFR-) in the PR description.
  • Update the matching doc page when behaviour changes.

Never

  • Import from another module's internal package.
  • Update or delete rows in sale*, payment, stock_movement, audit_log.
  • Throw from an SPI validator to block a synced sale.
  • Use double, float or JS number for money.
  • Edit a merged Flyway script.
  • Log secrets, PINs, tokens or personal data.
  • Add Redis, Kafka, Kubernetes or a new datastore without an ADR.
  • Disable a failing test to make CI green.

Task recipes (prompts that work)

Implement a feature from the catalogue 
Read Doc/ai/AGENTS.md, Doc/requirements.html (F-xxx and related BR-xx),
and the module section in Doc/modules.html. Propose the change as:
1) schema migration, 2) domain + tests, 3) API + OpenAPI, 4) sync scope if the
register needs it, 5) register-core + UI, 6) i18n, 7) docs update.
List which invariants (INV-xx) are touched and how each is tested. Then implement step by step,
running tests after each step.
Debug a production report ("sale missing", "stock wrong") 
Follow Doc/operations.html#debug-sale. Given receipt CMB01-R02-000154:
find the sale, its sync status, its stock movements and its audit entries.
Explain the root cause with evidence (log lines, rows) before proposing a fix.
Do not modify production data. Corrections are new records (INV-02).
Review a pull request 
Review this diff against Doc/dev-guide.html#review and Doc/security.html#security-checklist.
Flag any violation of INV-01..INV-15 with file:line and a concrete failure scenario.
Add a new industry module 
Follow Doc/extensions.html#add-extension. Use only existing SPIs unless you can show a concrete
case that needs a new one. Tables must be prefixed and reference core ids only.
Provide an end-to-end test with the module enabled and disabled.
