Cost & scaling

The architecture is cheap to run by design: registers do the heavy work, so the server mostly stores facts. One process and one database carry the product a long way. Spend more only when a measured trigger says so.

Prices are indicative The figures are rough monthly ranges in US dollars for small cloud resources in late 2026. They are meant for planning and comparing stages, not as quotes. Check current prices with the chosen provider before committing.

Cost principles

  1. Push work to the edge. Pricing, tax, search and receipts run on the shop's own hardware. The cloud only ingests facts and serves changes.
  2. One image, one database. No Kubernetes, Kafka, Redis or separate search cluster until a trigger metric demands it (P8).
  3. Static where possible. The admin web and catalog snapshots are static files on a bucket or CDN, which costs close to nothing.
  4. Pay for durability, not idle capacity. Spend on backups and PITR first. Skip HA standbys and multi-region until customers' contracts need them. Shops keep selling during an outage anyway.
  5. Measure cost per active branch every month, and price the product so that cloud + messaging + support is covered with margin.

Cost traps to avoid

  • Managed NAT gateways on some clouds cost a fixed hourly fee plus per-GB charges, often more than the app server itself. Use public subnets with tight security groups, or provider setups without NAT, at Stage 1–2.
  • Kubernetes control planes and node pools for a single service: a fixed cost plus a lot of operations work for one person.
  • Multi-AZ / HA everything from day one. Shops sell offline, so a short cloud outage is not a revenue outage. Add an HA database standby when contracts or scale require it.
  • Per-host APM pricing and high-cardinality metrics (one series per sale or SKU). Keep labels to tenant/branch at most.
  • Unbounded log retention and debug logs left on.
  • Sending SMS receipts by default. Make them opt-in and billable per message.

Tracking cost per tenant

  • Every month, a worker job records per tenant: sales count, rows written, storage used (partition sizes by tenant are estimated from row counts), sync bytes, messages sent, support tickets.
  • Tenant cost = shared infrastructure cost × tenant share of (rows written + sync bytes), plus direct message costs.
  • Admin dashboard metric: cloud cost per active branch. Target under $1 at Stage 2 and beyond (BG-5).
  • Set provider budget alerts at 80% and 100% of the monthly plan.
